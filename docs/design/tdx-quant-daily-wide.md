# 设计：TDX 量化日频宽表

## 需求链接

`docs/requirements/tdx-quant-daily-wide.md`

## 当前系统

`daily_bars` 保存价格，`financial_reports`/`financial_report_values` 保存财报双时间轴，`share_capital_history` 保存逐日股本，`corporate_actions` 保存分红送配，两个 `*_flat` 表保存真实观察日快照。`history_service.py` 已验证单标的 point-in-time 选择逻辑，但尚无持久化日频面板。

## 目标架构

- `quant_wide_service.py`：从归档表读取单标的有序序列，线性扫描财报、股本和事件，批量物化宽表。
- `quant_wide_cli.py`：选择当前标的、日期范围和重建方式，不访问网络。
- `repository.py`：创建宽表和构建审计表。
- `quant_daily_wide`：面向研究的稳定读取接口。

流程为：日线交易日骨架 → 过去价格窗口 → 公告日财报状态 → 生效股本状态 → 当日事件 → 精确观察日快照 → 幂等批量写入。

## 数据模型

`quant_daily_wide` 以 `(code, trade_date)` 为主键，字段分为：

- 身份：名称、市场、股票/ETF 类型；
- 行情：OHLCV、成交额、复权因子、行情股本字段；
- 历史特征：过去 1/5/20 日收益、对数收益、日内收益、振幅、5/20 日均价和 20 日量额均值；
- 财报状态：报告期、公告日、报告年龄、FN193–FN200；
- 股本状态：生效日、流通/总股本、收盘价乘股本的市值输入；
- 事件：当日行为计数/类型、现金分红、送股、配股、配股价、距最近行为天数；
- 快照：来源观察日、行情日、PE/PB/股息率/换手/Beta/市值和近期公告、回购、激励、解禁、大宗交易、停牌日期；
- 血缘：构建时间。

`quant_wide_build_runs` 保存开始/完成时间、代码数、写入行数、状态和消息。

## 接口

```python
build_quant_daily_wide(connection, codes, start=None, end=None, rebuild=False)
```

命令行：

```powershell
tdx-build-quant-wide
tdx-build-quant-wide --code 600000.SH 000001.SZ 510300.SH --start 2020-01-01
```

## 正确性约束

- 财报只有公告日不晚于交易日才进入活动版本集合；在活动集合中选择报告期最大者。
- 扩展快照按内部 `HqDate` 对齐交易日并保存真实观察日；基础快照使用同批观察日。不允许填入早于内部行情日的历史日期。
- 收益和均线只读取当前及更早日线，不写未来标签。
- ETF 通过当前 ETF 资产类型识别；指数成员关系不成为历史特征。

## 失败处理

- 每个标的单独事务；失败回滚当前标的并记录构建失败。
- `--rebuild` 只删除明确选择的代码和日期范围。
- 构建可重复运行，主键冲突执行更新。

## 备选方案

- SQL 视图：无需额外空间，但多层相关子查询对数百万行研究扫描过慢。
- EAV 特征表：扩展灵活，但横截面研究需要大量 pivot。
- Parquet：适合分析，但与当前 SQLite 管理方式不一致，且用户明确希望统一存储管理。

选择 SQLite 物化宽表，以读取性能和统一管理优先。

## 风险与验证

- 全量约三百万行，需测量构建时间和库体积。
- 股本单位和 FN 口径保留源值，市值字段明确为按原始股本计算的输入。
- 离线构造股票/ETF、公告切换和事件样例；真实库做多标的抽样及全库唯一性检查。
