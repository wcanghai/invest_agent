# 需求：TDX 每日增量与历史财务归档

## 背景

现有 `tdx-full-archive` 已能按证券和交易日增量写入日线，但财务、估值、基础资料和关系数据主要按采集日保存快照；`additional_data.py` 展示的历史财务、股本和公司行为接口尚未进入归档流程。

## 目标

- 提供可由操作系统每天定时执行的独立增量命令。
- 每次运行使用统一快照日期，幂等保存日线、基础资料、估值/行情快照、关系及其他会变化的信息。
- 保存带报告期和公告日的历史财务记录、历史股本和公司行为，支持后续 point-in-time 指标计算。
- 保留完整原始返回，不因当前字段解释不完整而丢失数据。

## 范围

### 包含

- 日线、`stock_info`、`more_info`、`market_snapshot`、`relations`、`gp_single` 的每日快照。
- `get_financial_data(report_type='announce_time')` 返回的 Fn193-Fn200 历史记录。
- `get_gb_info_by_date` 返回的股本历史。
- `get_divid_factors` 返回的分红送配和除权数据。
- `get_gpjy_value` 当日交易扩展数据的原始归档。
- 从现有数据库读取已归档标的的 `tdx-daily-update` 命令。

### 不包含

- 创建操作系统计划任务或启动真实全市场批量采集。
- 将未经验证的 Fn 字段直接物化为 PB、PE 等指标。
- ETF 持仓、基金净值等非当前 TQ 股票接口数据。

## 功能要求

1. 日线从数据库内每只证券的最后交易日后一日开始请求。
2. 历史数据从相应表的最后事件日向前重叠若干天请求，以吸收修订并通过主键幂等更新。
3. 一次运行跨越午夜时，所有快照仍使用启动时确定的同一日期。
4. 单只证券或单个附加接口失败不得回滚其他证券已成功提交的数据，运行结果记录失败数量。
5. 每日命令默认读取数据库中已有标的及分组，不依赖每天重新请求外部指数清单。
6. 原始数据与结构化历史数据必须分开保存。
7. 财务字段必须能够按字段名查询，新增 Fn 字段时不要求修改数据库表结构。
8. 必须提供按历史交易日读取“当时已公告财报”和“当时有效股本”的统一接口。
9. 历史 PB 计算必须显式指定已验证的每股净资产字段，不得默认信任未校验字段。

## 非功能要求

- Python 3.11+，公共函数带类型注解。
- TDX 调用通过可注入客户端隔离，测试不得访问网络或本机 DLL。
- SQLite 写入幂等；旧数据库只能做向前兼容建表，不删除既有数据。
- 数据库、日志和采集结果不得提交 Git。

## 验收标准

- 同一快照日期重复运行后，各快照表和历史表不产生重复记录。
- 新交易日仅请求缺失日线；财务、股本和公司行为使用各自增量起点。
- 财务表同时保存 `report_date` 与 `announce_date`。
- 历史指标输入不会使用交易日之后才公告的数据，旧报告期的更正公告不会覆盖更新报告期。
- 公司行为的现金分红、送股、配股和配股价可直接查询，不必解析 JSON。
- `tdx-daily-update --help` 可用，且无已归档标的时给出清晰错误。
- 全部离线测试与 `git diff --check` 通过。

## 风险与开放问题

- 本机文档只明确 Fn193-Fn200；字段名称与实测数值存在口径疑点，必须在计算指标前逐字段校验。
- 专业财务数据依赖通达信客户端预先下载，缺失时接口返回空数据。
- 历史财报可能存在更正公告；通过公告日和报告期联合主键保存，但同日同报告期的覆盖仍只能保留最新一次抓取。
