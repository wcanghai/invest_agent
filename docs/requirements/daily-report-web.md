# Requirement: 每日行情报告网站

## Background

当前日报以 Markdown 文件输出。用户需要通过浏览器查看，并要求每天的数据只在第一次获取时计算，之后永久从数据库读取。

## Goals

- 提供本地 B/S 架构的响应式行情报告网站。
- 当天报告首次访问时采集、计算并保存；当天后续访问不重复调用行情接口。
- 永久保存每日原始快照和 Markdown 报告，支持历史日期浏览。

## Users And Scenarios

- 单一可信本地用户打开首页查看当天报告。
- 用户选择历史日期查看已保存报告。
- 程序或其他客户端通过 JSON API 读取报告和历史日期。

## Functional Requirements

- `GET /` 展示当天报告；不存在时生成并入库。
- `GET /reports/{date}` 展示指定历史报告，不自动回填过去日期。
- `GET /api/reports` 返回已保存日期列表。
- `GET /api/reports/{date}` 返回结构化快照和 Markdown。
- `GET /health` 返回服务和数据库状态。
- 每个自然日最多保存一条成功报告。
- 生成失败不得写入不完整报告，页面应显示可理解的错误。
- 东方财富链接在新页签打开，且新页面不能反向控制日报页。
- 含涨跌幅的标的表在对应列名旁提供三态箭头，循环切换默认顺序、涨幅优先和跌幅优先；默认顺序与配置文件一致。
- 涨跌幅大于 3% 或小于 -3%、三年价格分位大于 80% 或小于 20% 时仅使用颜色、底纹等视觉效果高亮，不追加文字标签。

## Non-Functional Requirements

- SQLite 数据库落盘，进程重启后数据仍存在。
- SQL 使用参数绑定；Markdown 渲染禁止原始 HTML，降低脚本注入风险。
- 默认仅监听 `127.0.0.1`，不提供登录和公网暴露。
- 首次生成期间使用进程内互斥锁避免同一进程重复采集。

## Out Of Scope

- 用户账户、权限系统、云部署和多机分布式锁。
- 自动补算过去没有保存的日期。
- 强制刷新或覆盖已经保存的日报。

## Acceptance Criteria

- 空数据库首次请求当天报告时调用生成器一次并写入数据库。
- 同一天再次请求时不调用生成器，返回相同持久化记录。
- 重建服务实例后仍可读取已有报告。
- 历史页面、API、东方财富链接和移动端布局正常。
- 现有四个命令行入口继续工作，全部离线测试通过。

## Dependencies And Risks

- 首次生成依赖已登录的通达信客户端和外部网络接口。
- 多进程部署可能产生重复计算，但数据库唯一键保证最终仅保存一条；首版固定单进程运行。
