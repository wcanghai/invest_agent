# Requirement: 通达信量化价值研究数据域

## Background

现有 `daily_report` 面向日报，`tdx_data` 面向完整原始归档。新增第三个业务域
`quant_value`，只采集量化价值研究所需的数据，并产出可直接回测的时点一致因子表。

## Goals

- 通过通达信 TQ 获取股票、ETF 及 ETF 基准的历史行情和每日快照。
- 获取股票历史财报、股本、分红送配、基础资料和板块关系。
- 以 `announce_date <= trade_date` 选择当日可知财报，杜绝未来数据泄漏。
- 对股票和 ETF 分别计算适用的价值、质量、成长、风险和交易因子。
- SQLite 幂等保存，支持首次全量和后续增量同步。
- 使用多行业股票及宽基、行业、债券、商品、跨境 ETF 做真实接口验证。

## In Scope

- 独立 Python 包、CLI、SQLite schema、字段字典、代表性标的配置。
- 日线 OHLCV/成交额、基础资料、动态快照、专业财务、股本、公司行动、关系。
- ETF IOPV/份额/规模快照，以及有基准代码时的跟踪指标。
- 股票 PB、TTM PE/PS、自由现金流收益率、ROE/ROIC、利润率、现金含量、杠杆、
  流动性、成长、分红和价格风险指标。
- 数据覆盖率检查和代表性样本验证命令。

## Out of Scope

- 下单、自动交易、组合优化和投资建议。
- 数据库写入现有 `tdx_data` 或 `daily_report` 数据库。
- TDX 未提供的 ETF 历史净值、完整持仓、费率以及公司定性信息。
- 对缺失字段进行主观估算或用当前快照回填历史。

## Functional Requirements

1. `sync` 可按配置或代码列表执行区间采集；重复执行不得产生重复记录。
2. 增量同步从各标的最后交易日继续，并重叠最近 7 天处理修订。
3. 股票财务字段使用官方 FN 定义，保存原始 JSON 和长表数值。
4. `build` 生成一行一证券一交易日的 `factor_daily`，保留来源报告期和公告日。
5. 股票因子只引用交易日当时已公告数据；ETF 不套用股票财务因子。
6. `verify` 输出每个标的的行情、财报/IOPV、因子覆盖和关键缺失原因。
7. TDX 调用通过可注入网关隔离，测试默认离线。
8. `analyze` 使用分析日当时可见的数据，对股票给出估值、盈利质量、成长、
   安全性和股东回报评分，并列出优势、风险和数据提示。

## Non-Functional Requirements

- Python 3.11+，公开函数包含类型注解。
- SQLite 启用外键和 WAL；所有自然键有唯一约束。
- 网络失败按标的隔离并写入同步审计，不损坏已落库数据。
- 数据库、日志和验证输出均不提交 Git。

## Acceptance Criteria

- 离线测试覆盖幂等同步、公告日对齐、股票因子、ETF 跟踪因子和缺失数据。
- CLI 支持 `sync`、`build`、`verify`、`init`。
- CLI 支持按指定历史日期运行可解释的股票价值分析，年报公告前不得提前引用。
- 代表性标的真实同步后，股票至少有行情和历史财报，ETF 至少有行情；支持的
  ETF 同时具有基准跟踪或 IOPV 数据。
- `python -m pytest -q -p no:cacheprovider` 与 `git diff --check` 通过。

## Risks

- 专业财务数据需要先在通达信客户端完成下载，缺失时只能报告覆盖不足。
- TDX 的 ETF 跟踪接口按指数查询，部分债券、商品或跨境 ETF 可能没有可查询基准。
- 日内 IOPV 是观察时点数据；历史折溢价只能从部署后的每日快照逐步积累。

## Readiness

用户已明确要求直接构建并验证，边界足够清晰，Ready for design。
