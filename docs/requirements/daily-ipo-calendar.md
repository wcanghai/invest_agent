# Requirement: 日报新股新债发行日历

## Background

现有日报覆盖行情、市场宽度及多市场价格，但没有展示每日可申购的新股、新债和近期上市事件。本机通达信 TQ 提供当天及未来的新股/新债申购信息，AKShare 可补充中签率、正股、评级和上市日期。

## Goals

- 在每日行情报告中展示近期有操作价值的新股、新债申购与上市事件。
- 通达信作为当期申购日历来源，公开接口用于补全历史与上市字段。
- 任一补充接口失败时仍生成日报，并明确记录数据源警告。

## Users And Scenarios

- 本地投资者每天打开日报，快速确认今天及未来两周是否有新股或新债可申购。
- 用户查看最近三天及未来两周的上市事件，避免遗漏新上市证券。
- 网站首次请求生成报告时，发行日历和行情快照一起持久化，后续请求读取同一记录。

## Functional Requirements

1. 调用通达信 `get_ipo_info(ipo_type=2, ipo_date=1)` 获取今天及未来的新股、新债申购信息。
2. 调用 AKShare `stock_xgsglb_em(symbol="全部股票")` 补充新股中签率、上市日期等字段。
3. 调用 AKShare `bond_zh_cov()` 补充可转债正股、发行规模、评级、中签率和上市日期。
4. 将不同来源归一化并按“类型 + 申购代码”合并，通达信当期字段优先，公开源补全空缺。
5. 报告保留今天至未来十四天的申购事件，以及最近三天至未来十四天的上市事件。
6. 日报显示类型、名称、申购代码、申购日、发行价、申购上限、发行市盈率/评级、中签率、上市日、正股及来源。
7. 结构化快照增加 `ipo_calendar`，数据源异常加入既有 `warnings`。
8. B/S 首页显示发行事件数和今日可申购数，并提供今日及历史发行日历 JSON API。

## Non-Functional Requirements

- 通达信与网络调用必须封装为可注入调用，单元测试保持离线。
- 补充接口失败不能阻断日报生成。
- 日期、数字和缺失值必须稳健归一化，不能将 `NaN` 写入持久化 JSON。
- 不新增密钥、账号或公开服务监听配置。

## Out Of Scope

- 自动申购、交易下单、中签缴款提醒或账户市值额度计算。
- 新股、新债投资价值评分或收益承诺。
- 银行间市场全部普通债券发行日历。
- 对外公开或再分发第三方数据。

## Acceptance Criteria

- AC1：给定通达信返回值，可正确区分新股和新债并归一化核心字段。
- AC2：同一申购代码的通达信与公开源记录只输出一行，补充字段正确合并。
- AC3：超出观察窗口的旧记录不进入日报，今天及窗口内事件保留。
- AC4：公开接口异常时日报继续生成，并出现可读警告。
- AC5：Markdown 包含“新股新债日历”及表格字段；无事件时显示明确空状态。
- AC6：结构化快照包含 `ipo_calendar`，现有 CLI 和网站首次生成/持久化行为不变。
- AC7：发行日历 API 可以作为当天首次请求触发一次生成，后续请求复用同一持久化记录。

## Dependencies

- 本机已启动并登录的通达信客户端及 `tqcenter`。
- 项目现有 AKShare 依赖和公开数据源可用性。

## Risks

- 通达信接口不返回历史申购记录和上市日期。
- 东方财富等聚合页面字段或接口可能变化。
- 上市日期可能在发行过程中尚未确定，必须允许为空。

## Open Questions

- 当前采用十四天前瞻、三天回看作为固定日报窗口；后续如有需要可配置化。
