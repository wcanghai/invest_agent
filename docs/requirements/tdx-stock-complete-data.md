# Requirement: 通达信股票全维度数据试采集

## Background

现有 `tdx_history` 只持久化日线。通达信接口还能按股票获取公司行为、股本、财务、实时快照、扩展指标、专业交易数据和板块关系，需要先以十只不同板块和行业的 A 股验证实际可用性。

## Goals

- 从配置文件读取十只试验股票。
- 每只股票采集最近十年日线及当前环境可返回的全部安全、只读股票数据集。
- 使用 SQLite 幂等保存，重复运行不制造重复历史记录。
- 输出逐股票、逐数据集的成功状态、记录数、字段数和错误原因。

## Users And Scenarios

本地投研用户运行命令完成小样本试采集，检查数据库和汇总报告后，再决定是否扩大到全市场。

## Functional Requirements

1. 样本覆盖沪市主板、深市主板、创业板、科创板、北交所和多个行业。
2. 数据集包括日线、分红送配、市场快照、基础资料、扩展指标、股本、专业财务、GP 交易数据、股票单值数据和所属板块。
3. 日线关闭通达信缺失值填充；历史数据按自然键幂等写入。
4. 当前快照按采集日期归档；动态字段完整保留为 JSON，并建立字段目录。
5. 单个接口或股票失败不阻断其余采集。
6. 数据库、运行结果和汇总报告仅保存在本地，不提交 Git。

## Non-Functional Requirements

- 通达信访问封装在可注入数据源中，单元测试不得依赖客户端或网络。
- 不调用账户、持仓、委托、下单、撤单和用户板块写接口。
- 所有公开函数使用类型注解；用户输出为中文。
- 保存数据来源、采集时间、数据集状态和错误信息。

## Out Of Scope

- 全市场批量导入。
- 历史逐笔、全市场实时订阅和 Level-2 权限购买。
- 通达信公式结果、账户私有数据及任何交易操作。
- 将数据库或采集结果上传云端。

## Acceptance Criteria

1. 配置恰好包含十只股票，并标注样本类型。
2. 新命令可创建 SQLite schema 并完成离线假数据测试。
3. 重复写入日线、公司行为、股本、财务和关系数据不会重复。
4. 真实试运行输出十只股票的数据集可用性矩阵。
5. `python -m pytest -q -p no:cacheprovider` 和 `git diff --check` 通过。

## Dependencies

- 已启动并登录的通达信客户端。
- `D:\SoftWare\TDX\PYPlugins\user` 下的 TQ Python 接口。
- 专业财务数据是否可用取决于客户端本地下载状态和权限。

## Risks

- 通达信动态字段及返回形状可能随客户端版本变化。
- 当前快照在非交易时段仍可能返回最近交易状态。
- 北交所代码及名称可能发生迁移，实际名称以接口返回为准。

## Open Questions

无阻断问题。默认使用独立数据库 `data/tdx_stock_data.sqlite3`，避免影响已有全市场日线库。
